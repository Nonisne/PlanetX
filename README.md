# X行星之谜 · 推理工作台

一个**零运行时依赖**的网页版《X行星之谜》（*The Search for Planet X*，Ben Rosset & Matthew O'Malley 设计，Foxtrot Games / Renegade 出版）推理工作台，提供两种开局玩法：**记录模式**保留配合官方 app 的人工记录流程；**内置谜题模式**由服务端生成原创谜题、回答查询并判定对错。两种模式都由玩家自己推理，页面不提供自动解题或候选世界建议。

- 维护每位玩家的**时间轨**与全桌共用的**可见天窗**，位置显示为「第 N 圈／第 M 格」，耗时显示为「N 个时间单位」；
- 在**星图**上标出时间轨事件（X行星会议、学术研究阶段），并让你三态标注天体（可能存在／确定存在／不存在：点图标选）；
- 把每一次观测写进**操作记录**与**积分**表（勘测范围与数量、扫描结果、研究课题 A–F、学术研究与同行评审轨道、会议线索）；
- **联机**：时间轨、天窗、行动日志、公开论文与已发布会议线索共享；初始线索、勘测数量、扫描结果、研究所得线索和未公开的理论天体按玩家保密。

> 这是一个**非官方粉丝项目**，使用自制界面、图标与原创内置谜题，不是官方 app，也不包含官方谜题库。原游戏信息仅作玩法来源说明。

## 先选玩法，再创建对局

| 玩法 | 棋盘与人数 | 入口与结果来源 |
| --- | --- | --- |
| **记录模式**（`record`，默认） | 标准 12／专家 18 扇区；离线个人记录或联机记录，联机至少 2 人开局 | 「新对局」或「联机 → 创建房间」；继续手动填写官方 app 的观测、线索、评审、定位判定与终局答案 |
| **内置谜题模式**（`builtin`） | **仅标准 12 扇区，1–6 人；没有 Bot 或内置专家盘** | 「新对局」创建单人内置局；多人从「联机 → 创建房间」选择内置谜题，等人到齐再开始；查询与判定由服务端完成 |

`playMode` 是玩法，`modeId` 是棋盘（`standard`／`expert`），都在**创建之前**选择，不能把进行中的记录局转换成内置局。内置单人局也是一个服务器房间，需要服务运行，不是离线谜题。内置局开始后锁定玩家名单，不能中途加入。

内置开局每人收到 **4 条私有初始排除线索**，格式只会是「某扇区没有小行星／彗星／气体云／矮行星」，**不提供空域信息，也不直接排除 X行星**。记录模式的填写选项和服务端校验使用同一范围。研究 A–F 时自动获得自己的课题线索，每题只给一条规则；**基础规律、研究／会议线索与充分的勘测／扫描观测共同唯一确定完整棋盘**。服务端负责生成与校验，玩家仍靠观测和手写标注推理，不保证只读完六题就能直接解出全部位置。

初始线索与研究模板更新不会改写正在进行的对局。请先结束已有对局，再关闭并重新启动服务，新建对局使用修正后的线索；直接重启会丢失内存中的房间。

### 内置研究命题

A–F 只显示一种或两种普通天体名称，不提前泄露关系、量词或范围上限。六个命题不重复，每题只有一条事实，不再生成指定扇区的计数题或「联合轨道研究」。以下仅为表达格式示例，并非当前对局的线索：

| 命题示例 | 线索形式示例 |
| --- | --- |
| 小行星 | 所有小行星都位于一段不超过 5 个连续扇区内。 |
| 彗星和气体云 | 没有任何彗星与气体云正对。 |
| 小行星和彗星 | 至少有一个小行星与某个彗星相邻。 |
| 气体云和矮行星 | 每个气体云都位于至少一个矮行星的 3 个扇区以内。 |

- **连续范围**不指定起点，可以跨越最后一格和第 1 格；N 格是上限，不是固定的精确跨度。
- **相邻**为左右一格；**正对**为相隔半圈，标准盘相隔 6 格；**N 格以内**按最短环形距离计算，包含恰好 N 格。
- **至少一个**包括全部都满足的情况，不是「恰好一个」；**每个A**各自至少对应一个B，不要求每个B都被对应。
- 范围题只用于有多枚天体、且能提供有效范围信息的主题；某些布局可全部使用双天体关系题。研究面板有默认折叠的概念说明。

相对关系可能保留镜像等候选，需要结合实际观测；生成器不再为强凑静态唯一解而往一道题追加多句。全部 4,446 张合法标准盘仍保留在抽样空间中，会议选取会验证同一完整观测结果下的 X／真正空域歧义可被消除。设计与原版依据见 `docs/superpowers/specs/2026-09-20-research-templates-design.md`。

## 快速开始

项目根目录已提供一键启动和关闭：

| 系统 | 一键启动 | 一键关闭 |
| --- | --- | --- |
| **macOS** | 双击 **`一键启动.command`** | 双击 **`一键关闭.command`** |
| **Windows** | 双击 **`start-server.cmd`** | 双击 **`stop-server.cmd`** |

启动成功后自动打开游戏页面；**保留启动终端窗口**即可游玩。重复启动会核验并复用本项目已运行的同端口服务，不会重新开服务或清空现有房间。macOS 脚本已设置可执行权限，也会查找当前环境、Homebrew、Volta 或 nvm 中的 Node。

关闭脚本只关闭**当前项目目录内启动器登记的服务**，包括使用自定义端口启动的实例，不按端口或进程名强杀其他程序。未启动时再次关闭也不会报错。也可以使用命令行：

```bash
node start.mjs           # 本机 + 局域网都能访问（同桌各自设备可连）
node start.mjs local     # 只有本机能访问
PORT=5180 node start.mjs # 换端口（被占用时脚本会提示，不会抛 EADDRINUSE）
node start.mjs --open    # 成功启动后自动打开浏览器
node stop.mjs            # 一键关闭本项目登记的服务（也可 npm run stop）
node tests/all.test.js   # 运行全部回归测试
node audit/official-rules.audit.mjs  # 独立官方规则对照
```

启动后窗口里会打印**本机地址**与**局域网地址**，把局域网地址发给同桌的人即可。

不需要 `npm install`，没有任何运行时依赖。Node 18+ 即可（开发时用的是 Node 24）。

> **这个窗口就是服务器。** 双击关闭脚本、按 Ctrl+C 或关闭启动窗口都会停止服务，**内存里的房间会一起消失**（包括单人内置局，大家需要用新房间码重开），请先结束现有对局。只刷新原标签页且服务器房间仍在时，会按身份重连，恢复已获得的私有线索、阶段与本地标注。不要为腾出端口关闭正在服务对局的旧窗口；并行检查新版本可用 `PORT` 换端口，但两个实例的房间互不迁移。
>
> 本次更新前已启动的旧进程，以及直接执行 `node server.mjs` 的进程，没有一键关闭登记，请到其原终端按 Ctrl+C；脚本不会猜测并结束这些进程。更新脚本本身不会重启任何正在运行的服务。
>
> `.planetx/` 只保存本机控制端口和随机启动令牌，不是游戏存档；不要分享此目录或在服务运行时删除。控制服务仅监听 `127.0.0.1`，关闭请求需要私有令牌，拒绝浏览器跨站请求，不向局域网开放管理接口。目录已加入 `.gitignore`。
>
> `tests/all.test.js` 通过 `spawnSync` 为每个测试文件启动独立进程并继承终端输出，避免 DOM、存储和网络桩互相污染。HTTP/SSE 用例需要允许监听本机临时端口。
>
> Windows `.cmd` 文件只放 ASCII，中文提示由 Node 打印。macOS 若因复制文件丢失执行权限，可在项目目录运行 `chmod +x 一键启动.command 一键关闭.command` 后再次双击。

### 联机怎么开

| 场景 | 做法 |
| --- | --- |
| **同桌（同一个 Wi-Fi）** | 所有人打开 `http://<局域网IP>:5173/` → 一人「联机 → 创建房间」拿到 6 位房间码 → 其他人「联机 → 加入房间」输入房间码 |
| **只有一台电脑试双人** | 按 **Ctrl+N 开新窗口**（或在新标签页里重新输入网址），两边各自建房/加房。身份按**标签页**隔离，两个标签页就是两个玩家；⚠️ 别用"复制标签页"（会把身份一起复制过去） |
| **异地朋友** | 走私有网络：Tailscale（推荐），或 `cloudflared tunnel --url http://localhost:5173` 这类临时隧道 |

> ⚠️ 若别的设备连不上：多半是 Windows 防火墙拦了入站端口。用**管理员** PowerShell 跑一次：
> ```powershell
> New-NetFirewallRule -DisplayName "Planet X console" -Direction Inbound -LocalPort 5173 -Protocol TCP -Action Allow -Profile Private
> ```
>
> 🔒 这是**明文 HTTP**，唯一的访问控制是 6 位房间码——同一 Wi-Fi 内用没问题，**不要把这个端口直接映射到公网**。

## 行动与推理工作台

两种玩法都先选择行动与查询目标。**记录模式**再手动填写官方 app 的结果；**内置模式**只提交查询，由服务端自动返回本人可见的结果，不填写数量、扫描结果、研究正文或定位对错。

| 行动 | 共同操作 | 记录模式 / 内置模式 |
| --- | --- | --- |
| **勘测** | 选择天体，在星图点起点与终点；**整个范围必须在当前共享天窗内** | 手填数量 / 自动得到该范围的数量 |
| **扫描** | 选择一个可见扇区；每人最多 2 次 | 手选 app 结果 / 自动得到小行星、彗星、气体云、矮行星或空域 |
| **研究** | 选择尚未研究的 **A–F** 课题 | 房主填课题名、本人抄线索 / 课题名预设，查询后自动获得私有线索 |
| **提交学术研究** | 共享天窗到达或越过阶段标记时，全桌报数后按顺序提交 | 离线记录局手动完成阶段；联机记录局与内置局均使用房间阶段流程 |
| **定位 X行星** | 提交 X行星扇区和左右邻居的真实天体类型 | 手填 app 判定 / 服务端核对三项，错误继续，正确进入终局 |

正常行动耗时数值**没有因本次显示迁移改变**：勘测 **1–3 格 / 4–6 格 / 7–9 格分别 4 / 3 / 2 个时间单位**，扫描 **4**、研究 **1**、定位 **5**、等待 **1**。标准盘可见 6 格，因此 7–9 格勘测只适用于专家记录盘。彗星勘测的起止扇区都必须可能含彗星：标准盘为 **2、3、5、7、11**，专家盘再加 **13、17**。自己的连续两次行动不能都是研究，其他玩家行动或免费会议不能重置限制。

**X行星在扫描勘测中显示空域。**「空域」是观测结果，可能对应真正空域，也可能对应 X行星；内置基础规律与生成线索中的「真正空域」才指实际没有天体的扇区。内置查询到空域不会自动把该格确认成真正空域，也不会替你确认或排除 X行星。

> 为什么勘测/扫描只允许天窗内的扇区：实体版里你看不到窗口以外的天空，所以那些观测在桌上根本做不出来。天窗是全桌共用的一个盘（跟着最靠后的棋子走），所以**窗口一动，可选的扇区就跟着变**。


### 星图上的标注

**给星图自己标注**（不再是另一张网格表——那张表跟星图重复，已经删掉了）：

| 操作 | 效果 |
| --- | --- |
| 点一个天体图标 | 弹出三选一：**可能存在**（清除）／**确定存在**（发光）／**不存在**（划掉） |
| 「清空标注」 | 清掉本局所有手写标注（不影响记录） |

每个扇区里的六个图标是**固定的**（列与行都不动），整簇会**旋转到与该扇区的两条半径边平行**，所以圆盘外的图标不会读错行。标注跟着身份与房间号存在本机浏览器里，刷新不丢（联机时按「房间 + 身份」分开存）。

太阳周围的虚线轨道上有一颗**地球**：它始终位于当前可见半圆的角度中线上，跟随**共享天窗**转动，而不是跟随某一位玩家的个人时间。标准盘每移动一格转 30°，专家盘每格转 20°；跨圈时位置连续跟随。记录模式的撤销／校准也会更新它，内置模式不提供这些手动操作；终局天窗冻结时地球也保持冻结。这是天窗方向示意，不是额外天体或可点击的游戏目标。

### 当前计时口径

**一个时间单位对应棋子前进一格**；天窗只有在最靠后棋子的共享时间推进时才移动。位置统一显示「第 N 圈／第 M 格」，时长统一显示「N 个时间单位」，不再使用日历日期。

| 棋盘 | 一圈 | 从第 1 圈／第 1 格出发 |
| --- | --- | --- |
| 标准 12 扇区 | 12 个时间单位 | 前进 12 格后为第 2 圈／第 1 格，天窗回到 1–6 号 |
| 专家 18 扇区（仅记录模式） | 18 个时间单位 | 前进 18 格后为第 2 圈／第 1 格，天窗回到 1–9 号 |

本次不重算历史行动成本。摘要中的 `months`、`years`、`yearsLabel` 仅作为兼容别名保留，新显示使用时间单位与棋盘圈数，不拿旧字段名作界面标签。

### 记录表会自动写入

| 区域 | 自动写入来源 |
| --- | --- |
| 星图格子 | 初始排除线索与可直接确认的扫描／单格勘测事实；内置查询得到空域时不打「真正空域已确认」标记 |
| 研究课题 A–F（左侧参考区） | 共享课题名；本人研究后附上人工记录或服务端返回的私有线索 |
| 行动历史（底部通栏） | 每次行动的类型、范围、真实耗时及可见结果，按实际发生顺序逐条排成表 |
| 学术研究（左侧参考区） | 扇区 + 天体（未公开前显示「天体未公开」）+ 评审轨道位置 + 同行评审结果 |
| 会议线索 | 会议扇区 + 已发布线索；记录模式手填，内置模式到点自动发布 |
| 积分详情（底部折叠区） | 正确论文数、理论分、首先正确加成、定位分、合计 |

多格勘测的结果（"3–8 号里有多少个"）只写进操作记录，**不替你做逻辑推论**。内置扫描得到空域时只能排除四种普通天体；空域单格勘测数量为 1 时也不能据此确认真正空域。手写标注与推理仍由本人完成，服务端生成谜题时的唯一性校验不是玩家侧自动解题。

### 学术研究阶段（提交理论）

提交学术研究**不再是随时可做的免费行动**，它由时间轨触发：

1. **触发**：**天窗到达或越过学术研究扇区**时进入阶段，普通行动暂停。天窗起点跟随**最靠后（耗时最少）那枚棋子**；某个人冲到前面不会触发。一次跨过多个标记时按先后排队，处罚触发的新阶段排在旧阶段之后。
2. **同时报数**：每人在自己的界面上选 **0 到上限**篇论文（12 扇区标准盘 **1 篇**、18 扇区专家盘 **2 篇**）。选定后**不能更改**。

   实际上限还受本人剩余合法扇区限制：同一阶段同一扇区只能提交一次，已公开或本人所有主张都已提交的扇区不计入容量。没有合法论文可交时只能选 0 篇，仍可推进阶段，不会卡在无法履行的声明上。
3. **靠后的玩家先提交**：所有人都报完数后，界面上会排出顺序——**耗时最少的玩家先提交**（也就是下一步行动的那位）；**同扇区时先到者优先**。轮到你时选**扇区 + 天体**并确认；别人只看到**你在哪个扇区**提交了研究，**看不到你提交的天体**。
4. **评审轨道 4-3-2-1**：论文先落在最外面的 **4**；**本阶段结束后，所有未评审论文向内推进一格，零提交也推进**。同一阶段的论文一起移动：

```
第 1 个学术研究阶段提交 A、B → 推进后 A、B 都在 3
第 2 个阶段提交 C、D → A、B 到 2，C、D 在 3
第 3 个阶段提交 E、F → A、B 到 1（到期评审），C、D 到 2，E、F 在 3
```

同扇区、同阶段提交的正确论文共同获得最早提交奖励，不受网络提交先后影响。同一作者不能重复同区同天体的主张，也不能在同一阶段向同一区提交两种天体；不同阶段的不同主张可以保留。

离线记录局会保留被跨过的待处理阶段。可以提交后点击「完成本阶段」，也可以零提交直接完成；未处理完阶段和到期评审前不能继续普通行动。阶段结算或评审以后不能用「撤销最后一条」回退已经参与结算的记录。单人内置局与多人房间一样先报数、再按名额提交，不走离线记录局的阶段按钮。

> 「空域」不能作为理论提交：观测为空域的扇区可能就是 X行星，所以理论只能在**小行星／彗星／气体云／矮行星**里选。

5. **同行评审**：**按到期扇区编号从小到大处理**，只处理到达轨道 1 的论文。记录模式由作者或房主填写官方 app 判定；**内置模式由服务端自动评审，不显示手动判定入口**：
   - **正确**：该扇区的内容**对全桌公开**（同扇区其它研究一并揭晓：天体相同即正确、不同即错误），此后**任何人不能再对该扇区提交研究**；
   - **错误**：被否定的天体也公开；每篇新判错的论文使作者**前进 1 格，耗时 1 个时间单位**。同区同天体、同在评审格的论文批量结算；正确论文连带揭出的错误论文也处罚，按玩家顺序移动，重复请求不重复处罚。更外圈的论文不会因一次错误评审提前公开。

### 行动历史是一张表

展开页面底部的「行动历史」：第 1 列是记录顺序，之后**每列固定对应一名玩家**，自己的列会突出显示；单人局只有一个玩家列。**一行一次实际记录**，仅行动者的单元格填写内容，其余列用「—」占位；同一玩家连续行动也各占一行，不按个人棋位重新排序。

单元格先显示行动、范围和当时记录的真实耗时，点「查看结果」再看自己的数量、扫描结果或研究原文。会议和评审罚时使用独立公共事件行；已公开的论文结论以及终局揭晓后的定位记录可供全桌查看，其他私有结果不显示，也不会藏进 DOM 属性。

表头和顺序列固定，窄屏可在表格内横向滚动；最新记录位于底部，可点「查看最新」定位。展开状态及表格横纵滚动位置在标注、记录和联机更新导致的重绘后保留；切换对局或进退房间时清除旧记录的结果展开状态，不影响普通面板偏好。展开偏好不跨页面刷新保存。

### 积分

页面根据已结算的理论与定位记录统计积分；记录模式采用手填判定，内置模式采用服务端判定，终局再按完整答案结算剩余论文：

| 项目 | 分数 |
| --- | --- |
| 已被评审确认**正确**的论文 | 小行星 **2** · 彗星 **3** · 气体云 **4** · 矮行星 **4**（专家盘 **2**） |
| **最早阶段**在某个扇区提交正确理论的人 | 每个这样的扇区 **+1**，同阶段各作者共享 |
| **第一个**正确定位 X行星 | **+10** |
| 最后机会中正确定位 X行星的人 | 按冻结棋位落后首次发现者的格数，**每格 +2**（1–5 格对应 2–10 分） |

「空域」不能作为理论提交。分数在底部「积分详情」逐项列出；终局总分相同时，依次比较**定位分、最早提交奖励**，仍相同则并列获胜。计分常量集中在 `public/src/rules.js`，裁决在 `public/src/score.js`。

### 最后机会与全盘揭示

1. 正常定位支付 **5 个时间单位**。内置模式同时核对 X行星扇区与左右邻居的真实类型，不采信客户端的对错字段；错误继续游戏，首次正确后冻结共享天窗和终局棋位。定位的扇区、左右邻居在日志、摘要及房间快照中对其他玩家保密。
2. 仍落后的玩家按顺序各获得一次机会：落后 **1–3 格最多 1 篇**理论，落后 **4–5 格最多 2 篇**；也可改为尝试定位，或放弃。所有选择均不移动棋子。最终理论一次性提交，任何一篇不合法都不会部分写入。
3. 最后机会全部完成后，**内置模式自动揭示完整棋盘并结算积分**，房主也不能提前揭示或跳过他人。**记录模式**仍由房主按官方 app 输入 12／18 个扇区的完整答案。单人内置局没有其他玩家的最后机会，因此正确定位后自动揭示；离线记录局仍须人工填写揭示答案。
4. 记录模式的答案输入须完整、天体类型合法、恰好一个 X行星，且不与既有评审矛盾。两种模式都会按完整答案结算未评审论文，**不再处罚**；历史评审和历史罚时不被改写。最后显示公开棋盘、最终积分与获胜者。

记录模式不生成答案，也不校验人工输入整盘的全部数量与邻接规律；该模式的观测和答案仍来自官方 app。内置模式使用已通过生成器约束校验的原创棋盘，两者不是同一来源的谜题。

### 旧存档

离线记录存档保存记录、待处理／已完成阶段、撤销边界、冻结天窗与揭示结果。刷新可以继续，**既有耗时原样保留，不自动换算**。进入内置局不会把旧记录存档改成谜题；内置局与联机记录局都依赖服务器内存。只刷新原标签页可恢复身份、已获得的私有线索与本地标注；服务器重启则无法通过浏览器存档恢复房间或隐藏答案。

### 时间轨事件

会议与学术研究阶段挂在时间轨的**特定扇区**上（箭头＝共享天窗的第一个扇区）。按共享天窗的绝对进度检测到达／跨越，不按个人行动次数或日历日期触发。

| 模式 | X行星会议 | 学术研究阶段 |
| --- | --- | --- |
| 12 扇区（两种玩法） | 扇区 **10**，**1 次** | 扇区 **3、6、9、12** |
| 18 扇区（仅记录模式） | 扇区 **7、16**，**2 次** | 扇区 **3、6、9、12、15、18** |

星图外圈用图标标出（会议＝对话气泡，学术研究＝文稿），箭头走到时图标亮起、状态条提示"该开会了"。这些数字集中在 `public/src/rules.js` 的 `EVENT_SECTORS` 一个常量里。

### X行星会议：跟随共享天窗

**内置模式**在共享天窗到达或越过标准盘第 **10** 扇区时自动发布会议线索，全桌可见且不耗时；此前不会把会议正文发给客户端，不允许手动提前开会。若同时产生其他阶段事件，按阶段队列推进。

**记录模式**继续提示玩家去官方 app 查看会议规律并手动记录。房主在开局准备里抄好的文字可带入会议输入框，确认后成为会议记录；此模式中的手工预填不是内置谜题的保密机制。会议提示不阻塞普通行动，记录后不再重复提醒。

### 选棋盘：12 扇区还是 18 扇区

在创建对局之前先选玩法和棋盘，它们决定每圈格数、天窗宽度和上面那张事件表：

- **联机**：房主在「创建房间」表单里选；记录模式可选标准／专家，内置模式只支持标准，全桌跟随房间设置。
- **单人**：「新对局」中选择记录模式及棋盘，或选择标准内置谜题。选择只对新局生效，不转换当前对局。

### 其他约定

- **记录模式**可用「天窗 ◀ / ▶」手动对齐实体版，不消耗时间；内置模式不能校准天窗。
- 两种模式的勘测／扫描都校验共享可见范围，越界会被拒绝，不是只作警告。
- **记录模式**保留受阶段结算边界约束的撤销；**内置模式禁止撤销、手动评审、手动会议、课题／会议编辑、手工揭示与房主跳过**，避免利用已知结果回退或绕过流程。
- 页面**不做**候选世界推演、可能性提示或顾问建议——推理完全由你自己完成。

## 联机模式

同一张桌子上，一人开房间，其他人用 6 位房间码加入（各自用手机/平板/电脑打开本页 → 点「联机」）。

```bash
node server.mjs        # 联机房间 API 由同一个服务器提供
```

### 开局流程（大厅 → 开局准备 → 第一轮）

1. **大厅**：房主在「创建房间」选择玩法与棋盘，把 6 位房间码发给同桌；其他人点「加入房间」。行动面板列出玩家、房主与本人身份。
2. **开始游戏**：记录房间至少 2 人；内置房间允许 **1–6 人**，开始后不能再加入。想多人玩内置谜题，要在大厅等人到齐；「新对局」的单人内置入口会直接开始一人房间。
3. **开局准备**：所有人确认后进入行动阶段，具体内容按玩法区分：
   - **内置模式**：每人查看服务端发放的 **4 条私有初始排除线索**并确认准备；A–F 名称已生成，研究正文要行动后才获得，会议正文到共享天窗第 10 扇区才公开。不填写或修改这些线索。
   - **记录模式**：本人手填最多 12 条 app 初始排除线索，或勾选没有初始线索；房主手填共享 A–F 名称与会议预填文字（标准盘 10，专家盘 7／16）。别人准备好之前可重新填写；初始排除线索仍只对本人可见。
4. **行动阶段**：**耗时最少的玩家先行动，同位置先到者优先**，同一人可能连续行动。非当前玩家仍可手写标注和看自己的记录；手工会议记录只属于记录模式。

对局中编辑课题名／会议文字只属于**记录模式**。内置模式的房主也不能修改题目、手动判定或跳过当前玩家。

### 共享 / 私有

**共享**（像实体版桌面上的东西）：
- 时间轨：每人的棋子与耗时公开，行动只增加行动者的时间
- 共享可见天窗；手动微调仅限记录模式
- 行动日志：谁勘测了什么范围、谁扫描了哪个扇区（**结果不显示**）、谁研究了哪个课题（**内容不显示**）
- 学术研究：扇区、评审轨道位置、同行评审结果；被评审公开的扇区内容
- 已发布的会议线索、定位的成功／失败判定；记录模式的会议预填文字也共享，内置模式未到点的会议正文不共享
- **时间轨上的每一枚棋子**（第几圈／第几格、用了多少时间单位）与行动顺序
- 每个人的"是否已提交开局准备"、**A–F 课题名称**

**私有**（只有本人看得到的部分）：
- 勘测得到的**数量**
- 扫描得到的**天体**
- 每个课题下**本人手填或查询获得的线索正文**；内置模式未研究的正文不会预发
- 开局准备的**初始线索**
- **你提交的学术研究针对哪个天体**（别人只看到扇区），直到同行评审公开该扇区
- **你的定位扇区与左右邻居**，直到最后机会结束并完成全盘揭示

别人的私有字段在你的界面上显示为「结果未公开」，服务端也不会把这些字段放入你的 HTTP／SSE 快照，而不只是前端隐藏。内置完整答案保存在服务端 `room.puzzle`，揭示前不进入 `room.session`、客户端快照或 `public/` 静态文件；只有按规则获得的观测、线索与公开评审结论可见。你手写的星图标注存在本机浏览器里（按房间 + 身份分开保存），刷新不丢，但不支持换设备自动同步。

### 时间轨：每人一枚棋子

时间是**逐人**的，不是全桌一个时钟：

- 每人的棋子停在**自己**累计耗时对应的圈数与格位上。星图最外圈的小圆点就是棋子（颜色对应玩家，白圈＝你，亮圈＝正在行动的人）；**同一扇区里的棋子沿圆周依次排开，先到该扇区的人在最左边**。
- 一次行动结束后，**累计耗时最少的玩家**继续行动；花时间多的人在时间轨上更靠前，所以同一个人可能连续行动多次。
- 两人的棋子落在**同一扇区**时，**先进入该扇区的人先行动、也先在学术研究阶段提交**。
- **天窗（可见范围）是全桌共用的一个盘，并且跟着最靠后的那枚棋子走**：以他的扇区作为起点，所以**只有这个"最小值"被推着往前走时天窗才会移动**——某个人自己冲在前面不会让天窗动，也不会触发任何事件（这是"越过扇区才提醒"的判定依据：会议、学术研究都看天窗的起止扇区）。状态条上会写明"跟着最靠后的某某"。
- **仅记录模式**：房主的「跳过当前玩家」在普通行动阶段相当于让该玩家等待 1 个时间单位。内置模式没有房主跳过。

**房间存在服务器内存里**：服务器重启后房间消失，需要重新开一个。身份（房间码 + 令牌）保存在浏览器 **sessionStorage**：刷新会自动重连，而**同一浏览器的两个标签页算两个玩家**（正好用来一台电脑试玩一桌）。连接状态显示在顶栏。

临时网络错误或服务端 5xx 不会删除已保存的身份；确认服务恢复后可刷新重试。只有明确的房间失效或身份错误才清理令牌。切换房间后，旧请求不再锁住新房间或覆盖其状态；HTTP 与 SSE 快照共用单调递增的 `revision`，迟到的旧快照不会把行动历史和回合倒退。

消耗时间的动作：正常勘测、扫描、研究、等待、定位和评审错误罚时。论文提交、最后机会和全盘揭示不花时间。记录模式的房主可跳过普通行动或论文提交者，但不能跳过待评审；该模式中跳过当前最后机会等同放弃，不移动棋子。内置模式拒绝这些跳过请求；最后机会结束后自动揭示和计分。

### 房间 API（无依赖：HTTP + SSE）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/modes` | 棋盘列表 `modes`，以及 `playModes: ['record', 'builtin']`、`builtinBoards: ['standard']` 能力声明 |
| `POST` | `/api/rooms` | `{name, modeId, playMode}` → `{roomId, playerId, token, view}`；省略 `playMode` 时为 `record` |
| `POST` | `/api/rooms/:id/join` | `{name}` → 同上 |
| `GET` | `/api/rooms/:id/view?token=` | 该玩家的脱敏快照 |
| `GET` | `/api/rooms/:id/stream?token=` | Server-Sent Events，每次变化推一份该玩家的视图 |
| `POST` | `/api/rooms/:id/action` | `{token, action}`，返回 `{ok, view, ...}` |

`action.kind` 的常规动作包括 `survey` / `target` / `research` / `wait` / `locate`。`conference` / `nudge` / `review` / `undo` 是记录模式的人工操作，在内置模式中拒绝。房间级动作如下：

| kind | 谁能用 | 说明 |
| --- | --- | --- |
| `start-game` | 房主 | 大厅 → 开局准备；记录模式 ≥2 人，内置模式 1–6 人 |
| `setup` | 任何人 | 记录模式提交本人线索，房主还可交 `topics`／`conferences`；内置模式仅确认，使用服务端已发放的线索 |
| `setup-reopen` | 准备阶段的本人 | 重开自己的准备状态；记录模式可重填，内置模式不能替换已发放线索 |
| `set-topic-names` | 记录模式房主 | 对局中修改 A–F 课题名（`{names:{A..F}}`） |
| `set-conference-rules` | 记录模式房主 | 对局中修改会议线索（`{rules:{扇区:文本}}`，只接受本棋盘的会议扇区） |
| `research-declare` | 任何玩家 | 学术研究阶段报数：`{phaseId, count}`，`phaseId` 必须匹配 `view.research.id`，0 到本盘上限，一人一次 |
| `research-submit` | 轮到的那位 | 按顺序提交：`{phaseId, sector, objectType}`；旧阶段请求被拒绝，天体只对作者可见 |
| `skip-turn` | 记录模式房主 | 跳过当前玩家（学术研究阶段里＝让当前提交者放弃剩余名额）；内置模式禁用 |
| `final-theories` | 当前最后机会玩家 | `{theories:[{sector, objectType}]}`，不超过个人终局名额，整批原子提交 |
| `final-pass` | 当前最后机会玩家 | 放弃最后机会；也可用 `locate` 提交最后一次定位，费用为 0 |
| `reveal-objects` | 记录模式揭示阶段的房主 | `{objects:[...]}`，按 0 基扇区顺序填写完整棋盘；内置模式由服务端自动揭示，不接受手工请求 |

`theory`／`theory-complete` 只用于离线记录局；所有房间（含单人内置局）使用 `research-declare`／`research-submit`。API 的扇区索引从 **0** 开始，界面扇区编号从 **1** 开始；定位的左右邻居使用天体字符串而非图标数字编码。

内置查询**省略结果字段**：

| kind | 查询字段 | 由服务端产生、客户端值不可信的结果字段 |
| --- | --- | --- |
| `survey` | `type, start, size` | `count` |
| `target` | `sector` | `apparent` |
| `research` | `topic` | `name, text` |
| `locate` | `sector, left, right` | `correct` |

即使客户端附带这些结果字段，内置服务端也会按 `room.puzzle` 重算，不采信它们；记录模式仍需手填相应结果。身份令牌可以放在请求体、查询串或 `x-room-token` 头里。房间层校验权限、阶段与查询结果，复用 `public/src/console.js` 校验个人耗时、可见范围、扫描次数及研究限制。内置能力检查在建房 POST **之前**进行，不以记录局冒充创建成功的内置局。

## 当前能力与边界

| 项目 | 记录模式 | 内置谜题模式 |
| --- | --- | --- |
| 谜题与线索 | 人工记录官方 app 的结果，不生成或代判答案 | 原创约束生成；单／双天体命题各一条关系线索，结合充分观测后唯一确定完整棋盘，不宣称等同官方题库或难度 |
| 棋盘 | 标准 12／专家 18，离线与联机均可 | 仅标准 12，1–6 人服务器房间 |
| 理论与评审 | 4-3-2-1 轨道，人工填判定 | 同一轨道与阶段顺序，服务端自动评审与每篇错误 1 个时间单位罚时 |
| 定位与终局 | 人工填判定，最后机会后房主填答案 | 核对 X 与两邻居，正确后冻结，最后机会后自动揭示与计分 |
| 手动管理 | 保留受阶段限制的撤销、天窗校准、课题／会议编辑与房主跳过 | 不提供这些绕过自动判定的操作 |
| 推理辅助 | 手写标注与直接观测记录 | 同样不提供自动解题；空域观测不自动确认为真正空域 |
| 单人对手 | 个人记录，无 Bot | 可独自完成原创谜题，无 Bot；不是官方单人对手模式 |
| 持久化 | 离线记录在浏览器；联机房间在服务器内存 | 房间与隐藏谜题在服务器内存，重启不能恢复；本地标注不跨设备同步 |

两种模式继续使用逐人时间轨、共享天窗和同位置先到者优先。等待是本实现提供的 1 个时间单位辅助行动，不保证每次等待都能推动共享天窗。实体理论标记库存尚未模拟。

几个值得一提的设计：

- **两种玩法分开建局**。记录模式保留人工 app 流程；内置模式由 `server/puzzles.js` 生成谜题，隐藏答案只驻留服务端 `room.puzzle`，到合法揭示时才公开完整棋盘。生成器不作为客户端自动解题工具。
- **时间是日志的派生量**。每个玩家的耗时来自自己记录的 `cost`；评审罚时也有独立记录。论文阶段、撤销边界及终局冻结状态另外保存，已结算记录不能单独撤销。
- **共用规则，区分结果来源**。服务端复用 `console.js` 的行动校验；内置房间先计算真实结果，再执行阶段与自动结算。离线记录局保留自己的待处理阶段队列，不要求行动恰好停在标记上。
- **天窗只有一块**。`room.js` 在跑行动前把共享天窗时间钉进引擎状态（`windowTime`），所以勘测/扫描的可见性校验使用**全桌那个盘**，而不是行动者自己的时钟；地球跟随该天窗的中线。
- **脱敏发生在服务端**：`room.js` 只把该玩家能看的内容序列化出去（`PRIVATE_KEYS` 定义每种记录哪些字段私有），公开的研究（`revealed`）例外；前端拿不到别人的观测结果或未公开的天体。
- **刷新与重启不同**：离线记录可从本地恢复；房间刷新按身份重连，私有结果与本地标注继续隔离。服务器重启会丢失所有房间，历史耗时不会因显示迁移被重算。

## 后续路线

1. **房间持久化与观战**：把内存房间落盘、支持只读观战链接（例如给远程同桌的人看进度）。
