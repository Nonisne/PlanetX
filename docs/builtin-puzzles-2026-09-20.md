# 内置谜题、时间单位与空域术语迁移（2026-09-20）

本文记录已实现的行为、实际验证证据与部署边界。**2026-09-20 最终回归为 12 个测试文件、267 项全部通过，0 失败、0 跳过，包含 4,446 张合法标准盘的显式穷举。** 浏览器覆盖单人自动揭晓与计分、新生成谜题查询、双人私有线索与阶段同步、刷新恢复、专家盘 18 格换圈和窄屏布局。测试使用独立的本机 5192 端口，没有重启用户既有服务或迁移其房间。

## 玩法与支持范围

| 项目 | 记录模式 `record` | 内置谜题模式 `builtin` |
| --- | --- | --- |
| 默认行为 | 未传 `playMode` 时采用此模式 | 必须在建局前主动选择 |
| 棋盘 | `standard`：12 扇区；`expert`：18 扇区 | 仅 `standard`：12 扇区 |
| 运行方式 | 浏览器离线记录，或至少 2 人开始的联机记录房间 | 1–6 人服务器房间；单人也需要后端运行 |
| 结果来源 | 玩家填写官方 app 的观测、线索、判定与最终答案 | 服务端生成原创谜题并计算查询、评审与定位结果 |
| 单人玩法 | 个人记录，无 Bot | 独自解一道原创谜题，无 Bot，也不是官方单人对手模式 |

- 「新对局」选择内置谜题会创建并开始一个单人房间；多人使用「联机 → 创建房间」选择玩法，在大厅等人到齐再开始。
- `playMode` 是玩法，`modeId` 是棋盘。两者均在创建之前决定，**不支持把进行中的记录局转换成内置局**。
- 内置房间开始后锁定名单，不再接受中途加入；开始前最多 6 人。
- 专家盘仍可用于离线／联机记录，**内置专家盘与 Bot 尚未实现**。
- 本项目是非官方粉丝项目，使用自制界面、图标与原创内置谜题；本报告不作版权法律判断，也不把内置生成器描述成官方题库。

## 原创谜题与唯一性口径

生成模块位于 **`server/puzzles.js`**，只由服务端加载，不置于 `public/` 静态目录。标准盘使用以下库存与环形约束：

| 类型 | 数量 | 约束 |
| --- | --- | --- |
| 小行星 | 4 | 每颗至少与另一颗小行星相邻 |
| 彗星 | 2 | 只能位于 2、3、5、7、11 号扇区 |
| 气体云 | 2 | 每个至少与一个真正空域相邻 |
| 矮行星 | 1 | 不与 X行星相邻 |
| 真正空域 | 2 | 实际没有天体的扇区，不包括 X行星 |
| X行星 | 1 | 在扫描、勘测中按空域返回 |

生成的 A–F 六个课题与一次 X行星会议使用区间计数、邻接数量、环形距离等逻辑约束，不是逐格列出答案。**基础规律 + 六个课题的全部线索 + 会议线索唯一确定完整的 12 格棋盘**，不仅是唯一的 X行星位置。这里的唯一性不要求把玩家的初始排除线索也算入前提。

每人另获 **4 条私有初始排除线索**；各玩家只看自己的卡。初始排除线索按观测语义生成，不能用「不是空域」错误排除实际含 X行星的扇区。研究正文只有本人完成对应查询后才获得；课题名称共享，尚未研究的正文不预发给客户端。

服务端的候选枚举与唯一性检查用于**生成器验证**，不是游戏中的自动解题功能。玩家仍自行阅读线索、选择查询和手写标注；没有自动候选世界提示或替玩家完成推理。

## 已实现的内置对局流程

| 阶段／行动 | 行为 |
| --- | --- |
| 开局准备 | 发放每人 4 条私有排除线索；本人确认准备，不能手填或替换题目、课题正文、会议正文 |
| 勘测 | 提交天体与可见范围；服务端按棋盘计算数量，结果仅查询者可见 |
| 扫描 | 提交一个可见扇区；服务端返回观测类型，结果仅查询者可见 |
| A–F 研究 | 提交课题编号，服务端返回该课题的私有线索；每课题限一次，不能连续两次行动都研究 |
| 学术研究 | 共享天窗到达／越过 3、6、9、12 号阶段标记后暂停普通行动；各人先报 0–1 篇，再按顺序提交 |
| 轨道推进 | 论文从 4 格进入轨道，阶段完成后推进一格，零提交也推进；单人内置局同样使用房间阶段流程 |
| 同行评审 | 到轨道 1 的论文由服务端按到期扇区编号从小到大自动判定；每篇新判错论文罚 **1 个时间单位**，不重复处罚 |
| X行星会议 | 共享天窗到达／越过第 **10** 扇区后自动发布一次公共会议线索，不耗时，不允许提前读取或手动发布 |
| 正常定位 | 提交 X行星扇区、左邻居和右邻居的真实类型；服务端核对三项，消耗 **5 个时间单位** |
| 定位错误 | 记录错误结果，继续正常对局；客户端自行填写的对错无效 |
| 首次正确定位 | 支付正常定位耗时后冻结共享天窗与终局棋位，其他符合条件的玩家依次获得最后机会 |
| 最后机会 | 可按名额提交最终理论、尝试定位或放弃，不再移动棋子；此时完整答案仍不公开 |
| 揭示与计分 | 最后机会结束后自动揭示完整棋盘，结算未评审论文与最终积分，不对终局核对出的错误论文追加罚时 |

单人内置局没有其他玩家的最后机会，正确定位后可直接自动揭示与计分。多人最后机会的定位细节在全盘揭示前继续对其他玩家保密。正确评审可按既有规则公开相关扇区，但不会提前公开整盘。

**内置模式禁用人工旁路**：`undo`、`nudge`、`review`、`conference`、`reveal-objects`、`set-topic-names`、`set-conference-rules`、`skip-turn`。这些限制由服务端执行，不只是隐藏按钮。记录模式继续保留原有人工流程及阶段／权限限制。

## 空域：显示术语与观测语义

显示文案统一使用 **空域**；需要表达真实空扇区的基础规律和生成线索使用 **真正空域**。内部标识 **`Obj.EMPTY`／`'empty'` 不改变**。

**X行星在扫描勘测中显示空域**，所以「扫描结果为空域」并不等于「这里是真正空域」。标准盘的 2 个真正空域与 1 个 X行星，在这两种查询中都呈现为空域；气体云相邻约束中的真正空域则不包含 X行星。

- 内置扫描得到空域时，可记录四种普通天体的直接排除信息，但不自动确认真正空域或排除 X行星。
- 内置单格勘测空域、数量为 1 时，不自动把该格标成真正空域已确认。
- 多格勘测只保留数量，不自动推演其他扇区；确定性标记与手写推理分开。
- 理论仍只能提交小行星、彗星、气体云、矮行星，不能提交空域或 X行星。
- 旧历史审计报告保留当时用语，不以改写历史证据的方式完成此次术语迁移。

## 时间显示迁移

位置统一为 **「第 N 圈／第 M 格」**，持续时间统一为 **「N 个时间单位」**。标准盘 **12 个时间单位一圈**，专家记录盘 **18 个时间单位一圈**；从第 1 圈／第 1 格前进各自一圈，均显示第 2 圈／第 1 格。不再把专家盘进度套进固定的日历周期。

| 行动 | 时间单位 |
| --- | --- |
| 勘测 1–3 格 | 4 |
| 勘测 4–6 格 | 3 |
| 勘测 7–9 格（专家记录盘） | 2 |
| 扫描 | 4 |
| 研究 | 1 |
| 正常定位 | 5 |
| 等待 | 1 |
| 每篇新判错论文罚时 | 1 |
| 论文提交、会议、最后机会、全盘揭示 | 0 |

**数值成本不变，历史记录不重算。** 摘要的 `months`、`years`、`yearsLabel` 保留为兼容别名，当前显示使用 `units`、`laps`、`durationLabel` 及圈／格标签，不把兼容字段名当作界面用语。

每人累计自己的时间，耗时最少者先行动，同位置先到者优先；共享天窗只在全桌最小时间推进时移动。**地球始终跟随共享天窗的半圆中线**，不跟随某个玩家的个人时间，也不另作日历换算。标准盘每格 30°，专家记录盘每格 20°；内置终局冻结共享天窗时，地球的位置一同冻结。

## 服务端答案与隐私边界

| 位置／传输 | 揭示前的边界 |
| --- | --- |
| `server/puzzles.js` | 生成及验证模块仅在服务端，静态服务根为 `public/` |
| `room.puzzle` | 保存隐藏的完整答案、尚未获得的课题／会议线索和初始卡来源 |
| `room.session` | 不保存隐藏完整答案；只承载行动、阶段与按流程获得／公开的结果 |
| 本人 HTTP／SSE 视图 | 本人的初始线索、已研究正文、观测结果，以及允许公开的桌面信息 |
| 他人 HTTP／SSE 视图 | 不含本人的私有查询结果、未公开理论类型或尚未揭示的定位细节 |
| 浏览器身份与标注 | `sessionStorage` 用于身份重连，本地标注按房间与身份隔离；不是隐藏答案的存档 |
| 合法终局揭示 | 最后机会处理完毕后才通过 `revealedObjects` 等揭示状态公开完整棋盘 |

隐私过滤发生在服务端，不能用「前端把字段藏起来」替代。`room.puzzle` 不应被直接序列化为公共视图、摘要、浏览器会话或静态资源；按规则返回的局部观测、获得的线索与公开评审结论不等同于公开隐藏整盘。

**浏览器刷新与后端重启不是同一件事**：只刷新原标签页、且房间仍在运行时，可用原身份重连，继续获取已有私有线索和阶段，本地标注保留；后端重启会丢失**全部**内存房间，包括单人内置局。浏览器身份令牌和代码备份都不能复活已丢失的房间。

## API 与旧服务识别

`GET /api/modes` 继续返回棋盘列表 `modes`，并新增以下能力字段：

```json
{
  "playModes": ["record", "builtin"],
  "builtinBoards": ["standard"]
}
```

建房使用 `POST /api/rooms`：

```json
{
  "name": "玩家",
  "modeId": "standard",
  "playMode": "builtin"
}
```

省略 `playMode` 保留记录模式兼容行为。内置专家盘、未知玩法等不受支持的请求应明确拒绝，不能伪装成记录局创建成功。

通过 `/api/rooms/:id/action` 提交内置查询时，客户端只发送查询，不发送自报结果：

| `action.kind` | 查询字段 | 省略的结果字段 |
| --- | --- | --- |
| `survey` | `type, start, size` | `count` |
| `target` | `sector` | `apparent` |
| `research` | `topic` | `name, text` |
| `locate` | `sector, left, right` | `correct` |

客户端即使附带这些结果值，服务端也按 `room.puzzle` 重算，不采信它们。扇区索引在 API 中从 0 开始，界面从 1 开始；定位邻居使用天体字符串。开局 `setup` 在内置模式只确认准备，不接受客户端替换初始线索、课题或会议内容。

**建房前的兼容检查**：选择内置模式后，浏览器先读取 `/api/modes`；旧服务未声明 `playModes` 包含 `builtin` 时，在发出建房 POST **之前**提示更新并在现有对局结束后重启，不替换当前记录局，也不静默退回记录模式。建房响应若不是内置视图，也不会作为内置成功处理。新前端能显示选项不代表旧后端进程已经升级。

## 断线与长局边界保护

- **保留可恢复身份**：网络失败和 5xx 保留房间身份，提示恢复服务后刷新。明确的 401／403／404／410 才清理失效身份；旧恢复请求也不能清理或覆盖后来保存的新身份。
- **按房间隔离请求**：待处理行动绑定当前房间对象。离开旧房间不锁住新局；旧响应、失败通知及 SSE 回调不会干扰新房间。
- **防止状态回退**：HTTP 与 SSE 返回同一套 `revision`。加入、开局、准备及其他成功行动均推进版本，包括不增加日志的阶段操作；拒绝请求不推进版本。客户端忽略低于当前版本的快照。
- **拒绝无法完成的论文声明**：服务器按本人尚可提交的不同扇区计算 `research.maxDeclare`，界面同步禁用超容量选项。没有合法论文时可选 0 篇继续推进；容量计算只使用公开锁定扇区与本人论文，不读取隐藏谜底或他人未公开主张。

上述问题先以失败回归复现，再验证修复。长局测试使用 21 篇合法提交序列耗尽可交主张，确认零提交后仍能继续定位；专家记录盘仍允许合法的两篇提交。

## 部署与回退指引

> **本次包含前端与后端更新，不能沿用历史前端布局版本「只刷新、不重启」的部署说明。不要为了测试或启用内置模式重启仍有活跃对局的旧服务。**

1. **先等现有对局结束**，告知同桌参与者维护窗口。房间仅在内存中，停服会删除所有联机记录房间和内置房间，没有无损热迁移。
2. 现有迁移前文件备份为 **`/private/tmp/planetx-before-builtin-20260920.tgz`**。它是代码／文件回退点，**不是内存房间快照**，也不是已运行对局的恢复工具。
3. 在同一维护窗口成套部署前后端，包括 `server.mjs`、`server/puzzles.js` 和 `public/` 中相应更新；不要把只替换前端资源视为升级完成。按原有启动方式计划重启服务，再让浏览器刷新。
4. 用新进程的能力接口确认部署。默认端口的只读检查命令如下；若使用其他端口，应对应修改：

   ```bash
   curl -fsS http://127.0.0.1:5173/api/modes
   ```

   响应应包含 `playModes: ["record", "builtin"]` 与 `builtinBoards: ["standard"]`。若没有，不要强行向旧进程发内置建房请求；核对运行目录、进程与端口，仍需先结束活跃对局再维护。
5. 所有参与者刷新页面后**新建**所选玩法的房间，使用新的房间码。原有离线记录与手写标注不做静默成本换算，不能拿旧房间令牌恢复已重启清空的房间。
6. 若需在旧局进行期间并行检查新版本，可另用端口启动独立实例；两个实例不共享房间，这不是旧局迁移方案。本次 QA 使用的是独立 5192 端口实例，未重启用户既有服务。
7. 如需回退，同样先等新版本的活跃对局结束，在维护窗口成套恢复备份对应的前后端并重启，然后新建房间。回退代码也不能恢复已丢失的内存对局。
