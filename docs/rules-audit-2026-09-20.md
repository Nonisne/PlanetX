# PlanetX 官方规则一致性审计

审计日期：2026-09-20。对象：当前 `planet-x-web` 0.3.0 工作目录。

## 结论

当前实现可以运行，但不能视为符合正版规则的完整记录台。除明确的产品简化外，存在会改变行动顺序、暴露私密信息、漏掉评审与终局机会、影响得分的实现问题。

- 原有测试：6 个文件、101 项全部通过。
- 新增独立规则审计：23 个定向检查，7 项通过，16 项不符，0 个用例准备错误。
- 浏览器抽查：标准模式启动、切换专家模式成功；界面确实显示错误的行动成本，以及缺少 13、17 的专家彗星提示。
- 这不是整体测试覆盖率统计；这些检查是根据规则和可疑分支定向选择的。
- 本次没有修改业务实现，没有修复这些问题；只增加审计脚本、证据与本报告。

### 为什么原有测试没发现

原有测试主要验证当前实现设定。一些断言本身固定了错误成本和“定位公开且立即终局”等行为；另一些只覆盖单人连续研究、有人提交论文的阶段、主动填写错误的单篇评审，没有覆盖上述多人交错、零提交、连带罚时、并列首发场景。101 项全绿不能证明符合规则书。

R11 使用纯引擎夹具并跳过阶段门禁，只检查必须独立成立的重复论文约束；R09、R10、R16 使用已到指定轨道位置的论文夹具。其余对局复现尽量通过公开房间动作推进。夹具准备错误会独立列为 `harness-error`，不会伪装成规则不符。

R14 针对导出的胜者计算函数；当前界面主要展示分数表，不应把它描述成已观察到的“胜者弹窗显示错误”。

## 四、终局与计分需要一起处理

规则书第 16–17 页要求：首次成功者支付定位成本后冻结用于终局计算的棋位；符合条件的其他玩家按顺序获得最后得分机会，这些机会不再移动棋子；之后揭晓全部扇区并结算仍未揭晓的论文。

当前除了 R07，还缺少全图揭晓和最终论文确认的独立流程。正常评审只允许轨道 1 的论文填写结论，不能替代终局对所有剩余论文的揭晓。相关门禁在 `public/src/console.js:391`。

**不要仅凭 `locatePointsFor` 的命名就直接翻转公式。** 界面确实误写成“按落后格数每格减 2”；官方对最后成功者按冻结棋位的落后格数每格计 2 分。但 `scoreBoard` 当前传入的是两人定位记录的行动前时间差，不是规则中的落后格数：当首次定位成本为官方 5 格时，现有表达式恰好等价于正确计分。P07 用落后 1–5 格的五组夹具验证了这一点。

因此应统一“行动前时间 / 行动后棋位 / 终局冻结棋位”的定义，修复成本和最后机会流程，改正说明，并用完整终局用例验证；不能孤立地修改减法符号。

## 五、明确的产品边界与未覆盖项

- 不生成谜题、不替官方 App 判断定位对错、不自动演绎推理：符合项目声明，不作为缺陷。
- 用“月”展示时间、增加等待和手动天窗微调：属于产品扩展；单位改名不能解释移动格数不同。
- 官方单人模式包含 App 管理的 Bot；当前单机只是个人记录台，不能宣称已实现官方完整单人玩法。
- 会议线索允许提前填入并共享、论文选择只锁篇数而不是预选的天体：属于需要确认的产品简化，不计入上述 16 项已复现不符。
- 未完成实体论文标记库存耗尽、整桌长局、断线重连、跨设备、移动端布局、会议和评审连续跨越顺序的穷尽验收。
- 当前目录不是 Git 仓库，未做提交历史或差异审查。

## 七、建议处理顺序

1. 先修定位信息脱敏、错误定位不中断、行动成本、本人连续研究限制。
2. 补完整论文阶段：每阶段推进、重复/冲突论文约束、公开评审、连带罚时与幂等性、并列首发标识。
3. 建立最后机会、冻结棋位、全图揭晓、最终论文计分和胜者裁决流程。
4. 让单机复用阶段事件机制，修正规则文案，最后补双客户端与完整终局验收。

以上是建议，不代表本次已经执行修复。
