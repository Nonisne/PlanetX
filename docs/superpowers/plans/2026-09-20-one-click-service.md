# 一键启停实现计划

## 范围与设计

- macOS 增加项目根目录的 `一键启动.command`、`一键关闭.command`；Windows 保留 `start-server.cmd` 并增加 `stop-server.cmd`。
- 启动继续使用现有前台服务窗口，成功监听后打开浏览器；重复启动复用已核验的同项目服务，不重启或丢弃房间。
- 关闭通过仅监听本机的、随机令牌保护的控制通道完成，不按端口杀进程，也不使用 `killall node` 或未经核验的 PID。
- 每个端口的启动记录放在项目私有 `.planetx/` 目录，不对浏览器或局域网公开。关闭脚本处理本项目启动器登记的服务；无法核验的旧服务保持不动。
- macOS 入口兼容当前 nvm 安装与常见 Node 路径；缺少 Node 时给出明确提示，不自动安装依赖。
- 停止会丢失内存房间，脚本和说明明确提示。编写和测试期间不启停用户已有服务。

## 验证结果

- 初始 6 项测试在允许本机监听后全部因功能缺失失败；实现后通过。补充并发启动、非法端口和 Mac 入口后，9 项启停测试通过。
- macOS 入口使用精简 Finder PATH，实际加载当前 nvm 中的 Node，从其他目录启动中文／空格路径的临时副本；浏览器调用使用替身，核对页面就绪后打开正确地址。
- `PUZZLE_EXHAUSTIVE=1 node tests/all.test.js`：13 文件、276 项通过，0 失败、0 跳过。输出为 `audit/evidence/one-click-service-tests-2026-09-20.txt`。
- Node 语法、Bash／Zsh 语法、Mac 入口执行权限通过。Windows `.cmd` 保持 ASCII，当前 Mac 环境未进行 Windows 实机验证。
- 测试服务均在临时项目副本，未启动或关闭真实项目目录中的已有服务；没有改变游戏、房间或谜题实现。

## 约束

不新增依赖、不改变谜题或房间规则、不重启现有用户服务、不创建分支或提交。新增代码不使用单字母变量或内联注释。测试使用独立临时目录与随机本机端口。
