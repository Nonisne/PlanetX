# 规则、内置谜题与星图工作区改进

用户已确认本方案，并补充同扇区后到者领先、落后者优先行动与提交论文。

## 规则与隐私

- 内置模式仍为标准 12 扇区、1–4 人；保留记录模式和现有积分数值。
- 每人独立选择 0、4、8、12 条初始线索，默认选择 4；领取后锁定，重复请求不重新发牌。领取前不可准备。
- 服务器预生成每座位 12 条不重复、非基础规则直接蕴含的排除线索，按选择发前 N 条；未领取线索和别人的线索均不进入视图。
- 领取成功后的权威视图立即同步本人的排除标记，刷新也能恢复；不覆盖无关手写标记。
- 彗星只能在质数编号扇区：禁止无效理论，隐藏无效图标，限制勘测两端并保留天窗约束。
- 同一玩家可在后续阶段对未公开扇区提出另一种天体；不能重复同天体，也不能同阶段对同扇区提出两种天体。正确公开的扇区不再可选。
- 理论阶段与会议在天窗起点离开标记扇区时触发；跨多个事件时按经过顺序处理，兼容惩罚和终局冻结。
- 绝对耗时较少者先行动；同耗时早到者在后、晚到者在前，早到者先行动和提交论文。星图按顺时针方向表现前后，不按屏幕左右排序。

## 谜题

- 保留 4,446 个基础合法盘面用于验证；仅从其中可被相对关系会议区分的 4,428 个均匀抽题。
- 过滤已证实无法区分的 18 个盘面，不把过滤集合当作玩家可知的推理条件。
- 会议仅给 X 与一种普通天体的一个相对关系（相邻、相对或 N 格内，含无／至少一个／全部量词）。
- 普通 A–F 研究仍为六个不同课题、每课题一个事实；不增加自动解题辅助。

## 界面

- 初始线索领取选择与准备分开；领取后自动标图。
- 扇区天体图标略增间距；彗星固定槽位在非法扇区留空。
- 左侧论文进度改为两列表格：扇区；玩家图标与轨道位置。不泄露他人未揭示天体。
- 普通行动不显示等待与提交论文；触发阶段仍保留专用论文表单，增加内边距。
- 积分按每玩家两行表格：天体及单位分值／首对奖励／定位 X／合计，对应实际得分。不重复计算首个定位 X 的 10 分。
- 基础规则明确标准 1 颗矮行星、专家 4 颗。

## 共享接口

- `INITIAL_CLUE_COUNTS = [0, 4, 8, 12]`，`isCometSector(mode, sector)` 接受零基扇区。
- 领取动作：`{ kind: 'claim-initial-clues', count: 4 }`。
- `mySetup.initialClueCount` 初始为 `null`，`mySetup.cluesClaimed` 初始为 `false`；领取后设置真实值。
- `game.theoryOptions` 为 `{ sector, types }[]`，仅包含可提交的零基扇区及天体；由共享核心按照本人历史、当前阶段和公开锁定计算。
- UI 使用 `handlers.claimInitialClues(count)`；本地选择存于 `ui.initialClueCount`，默认 4。

## 边界

不修改一键启动／关闭脚本，不重启现有服务，不变更正在运行的房间；不提交 Git、不新建分支、不覆盖既有未提交更改。
